Architecture · layer by layer

TIC-VLA, drawn

Every block below is a real module with the shape the code gives it. The slow branch runs once per plan and leaves a 128-dimensional trace; the fast branch reads that trace thirty times a second. Where they meet is deliberately narrow — that narrowness is the design.

02 Inside one cross-attention block

Three of these, stacked, are the entire controller. Post-norm, cross-attention only — the 30 queries never attend to each other, so the plan's smoothness is whatever the shared context implies.

03 Two stages, two losses, no bridge

There is no joint objective anywhere in the codebase — no weighted sum, no alternating schedule. This diagram is what trains, and what does not.

Why this matters for what we measured

Whatever steering competence TIC-VLA has was learned by 10.27 M parameters reading a frozen 128-dimensional summary — not by the 1.9 B model that produced it. The language model is never once penalised for a trajectory that misses.

That is the same wall from the other side. Qwen3.8-27B could not write a positive y inside an (x, y) tuple; TIC-VLA does not solve that problem, it routes around it — the lateral sign is never asked of the language model at all. It comes out of a regression head that was fit to real trajectories.
